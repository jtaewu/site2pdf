# ADR-003. 인쇄 렌더링과 통합 PDF 병합

- 상태: **승인됨** (2026-11-24, Phase 0 결정 D-01~D-15 권장안 확정)
- 날짜: 2026-11-24
- 근거: `output/audit-report.md` §4.3–4.4, `output/poc/render.json`, `output/poc/merge.json`

## 결정
### 렌더링
1. `emulateMedia('print')` 후 **범용 인쇄 CSS**를 주입한다(06-technical-design §3 + 표 셀 줄바꿈 + 이미지 최대 폭).
2. `position: fixed/sticky` 요소는 기본으로 숨긴다(헤더가 본문을 가리는 문제 방지).
3. 사이트별 품질 조정은 **설정값**으로만 한다: `contentSelector`(본문만 인쇄), `readySelector`(렌더 완료 신호), `hideSelectors`. 코어 코드에 사이트 이름·선택자를 하드코딩하지 않는다.
4. 자동 품질 검사 두 가지를 기록한다. (a) 인쇄 폭 기준 **가로 넘침 요소**, (b) DOM 텍스트 대비 PDF 텍스트 **커버리지**. 이 검사는 육안 검수를 대체하지 않는다.

### 병합
5. **방식 A (페이지별 PDF → pdf-lib 병합)** 를 MVP 기본으로 쓴다.
   - 장 북마크 = 페이지 제목, 하위 북마크 = 각 페이지 PDF의 제목 북마크(2단계)
   - 포함된 페이지를 가리키는 URI 링크는 **PDF 내부 이동(GoTo)으로 변환**하고, 대상은 페이지 첫 장으로 한다.
6. 방식 B(본문을 하나의 HTML로 합쳐 1회 인쇄)는 후보로만 기록한다.

## 근거 (PoC 결과, 정적 fixture 5페이지)

- A는 FR-06(페이지별)과 FR-07(통합)을 같은 산출물에서 만들고, manifest의 "원본 URL → 출력 페이지" 대응이 단순하다.
- B는 앵커까지 정확하지만, 여러 페이지 CSS가 한 문서에 섞이고, 대규모(수백 페이지) DOM 메모리 부담이 있고, `contentSelector`가 필수다.

## 육안 검수에서 발견한 한계
- v1: 고정 헤더가 2페이지 상단의 코드 4줄을 가렸다. PDF 텍스트에는 남아 있어 **커버리지 검사로는 탐지되지 않았다**.
- v2/v3: `overflow-wrap: anywhere` 때문에 표 셀이 "E1/0", "코/드"처럼 글자 단위로 끊겼다. 셀 단위 줄바꿈 규칙의 추가 튜닝이 필요하다.
- 차단된 외부 이미지는 깨진 이미지 아이콘 + alt 텍스트로 출력된다. manifest 경고로 기록한다.

## 후속
- FR-10(북마크)은 PoC상 구현 비용이 낮다. Should로 유지하되 Phase 2에 포함할 것을 제안한다(보고서 D-07).
- 앵커 단위 내부 링크(A 방식)는 Chrome PDF의 named destination 활용 가능성을 Phase 2에서 확인한다.
