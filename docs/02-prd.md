# 02. PRD — site2pdf

> 상태: 제품 요구사항 초안 / 버전 0.2 / 2026-11-24

## 1. 배경과 문제
웹사이트의 여러 페이지를 하나의 읽기 쉬운 PDF로 보관·전달하려면 페이지마다 인쇄해야 하고, 메뉴 순서·코드·표·링크를 잃기 쉽다. 특정 문서 플랫폼에 의존하지 않는 변환 도구가 필요하다.

## 2. 제품 비전
사용자가 **권한 있는 사이트 URL 또는 로컬 정적 사이트**를 지정하면, 사이트의 하위 페이지를 제한적으로 탐색하고 대상 페이지를 선택하여 검색 가능한 PDF를 생성한다. **KICC 개발자 문서 변환은 첫 사용 사례일 뿐 코어 요구사항이 아니다.**

## 3. 사용자
- 개발자/운영 담당자: 자료 보관, 내부 공유, 오프라인 매뉴얼 제작
- 문서 담당자: 문서 변경에 따른 PDF 재생성
- 검수자: 누락·잘림·접근 권한·재배포 여부 점검

## 4. 목표/성공 지표
- 서로 다른 웹사이트 구조 **2종 이상**에서 데모 성공
- 대상 페이지 목록·제외 사유를 기계 판독 가능한 파일로 출력
- PDF에서 한글/영문 텍스트 선택 및 검색 가능, 코드/표/이미지 주요 샘플에서 잘림 없음
- 탐색 폭주·사설망 접근·사이트 차단 우회를 유발하지 않음

## 5. MVP 기능 요구사항
| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| FR-01 | URL 또는 로컬 정적 사이트 입력 | Must | 입력 유형 검증, 원격은 HTTPS 원칙 |
| FR-02 | 사이트 범위 설정 | Must | origin/path prefix/deny 패턴 밖 URL은 탐색·출력 금지 |
| FR-03 | 하위 페이지 탐색(discover) | Must | 링크 기반 페이지 목록 수집, 중복 정규화, 순서 기록 |
| FR-04 | 안전한 탐색 제한 | Must | 최대 깊이/페이지/시간, 요청 간격, robots/정책 확인, 리다이렉트 검증 |
| FR-05 | 페이지 포함·제외 선택 | Must | 구성 파일 allow/deny 및 발견 목록 선택 방식 지원 |
| FR-06 | 페이지별 PDF 생성 | Must | 각 선택 페이지를 PDF로 출력, 실패 기록 |
| FR-07 | 전체 통합 PDF 생성 | Must | 지정 순서대로 병합, 원본 URL/제목 매핑 |
| FR-08 | 한글·표·코드·이미지 처리 | Must | 대표 fixture에서 내용 누락/잘림 없음 |
| FR-09 | 결과 보고서 | Must | 페이지별 상태, 에러, 실패 자산, 출력 파일·원본 정보 포함 |
| FR-10 | PDF 목차/북마크 | Should | 통합 문서의 장 이동 가능 (기술 PoC 후 범위 확정) |
| FR-11 | 그룹별 PDF | Should | 구성된 URL prefix/그룹별 추가 PDF 생성 |
| FR-12 | 로컬 빌드 오프라인 모드 | Must | 외부 네트워크 요청 없이 처리 가능 |
| FR-13 | 메타데이터/파일명 설정 | Should | 제목/생성일/파일명 지정 가능 |

## 6. 비기능 요구사항
- **보안**: SSRF 차단, URL 경계 재검증, sandbox 브라우저, 스크립트/다운로드·외부 리소스 정책, 비밀정보 로그 마스킹.
- **윤리/법적 사용**: 승인된 사이트만 대상으로 하고 저작권·이용약관·robots 준수, 로그인 우회·차단 우회 금지.
- **안정성**: 장애 시 제한된 재시도, 부분 실패 보고, 무한 탐색 방지, 명시적 종료 코드.
- **재현성**: 설정·입력 URL·방문 순서·프로그램 버전·실패 내역을 manifest에 기록.
- **접근성**: 가능한 한 PDF 텍스트 검색/복사 유지, 이미지 단순 스크린샷 PDF 금지.

## 7. MVP 제외
- 로그인 자동화/계정 관리/캡차 해결/우회 프록시
- 임의 인터넷 전체 크롤러, 다중 도메인 자동 확장, 우회 수집
- 자동 대외 배포, SaaS, GUI, DB, 예약 실행, 파일 첨부 자동 다운로드
- DOCX/EPUB 변환, AI 요약, 범용 콘텐츠 완전 복원 보장

## 8. 핵심 사용자 흐름
1. 입력(URL 또는 로컬 폴더)·승인/허용 범위 설정
2. `audit` → 범위/의존성 진단
3. `discover` → 페이지 목록 생성·검수
4. `generate` → 페이지별/전체 PDF 출력
5. `validate` → 누락·출력 상태 확인 및 담당자 육안 검수

## 9. 수용 기준
- FR-01~09, FR-12 Must 완료 및 테스트 통과
- 인증/방화벽 차단 사이트 우회 없음
- 탐색이 origin/path/제한값을 벗어나지 않음 (리다이렉트 포함)
- 동일 문서 대상 목록과 PDF 순서가 manifest로 확인 가능
- KICC 등 실제 외부 배포는 별도의 내용·권한 승인 절차를 거침

## 10. 남은 결정
원격 페이지의 동적 리소스 허용 범위, robots 판정 정책, 사이트별 인쇄 CSS, 목차/북마크 수준은 `09-open-questions.md`와 PoC에 따라 확정.
