# 01. 입력 유형 및 사전 진단 (Phase 0)

## 범용 입력 모델
- **원격 URL 모드**: 소유/명시적 수집 권한을 가진 `https://` 사이트를 지정. 시작 URL에서 정해진 범위만 탐색.
- **로컬 사이트 모드**: 관리자가 제공한 정적 HTML 디렉터리 또는 로컬 빌드를 읽고 PDF 생성. 외부 네트워크 접근 금지.
- 원본 Markdown/MDX를 직접 읽는 기능은 **향후 확장 후보**; MVP는 브라우저 렌더링 가능한 HTML을 기본 입력으로 삼음.

## 진단 항목
| 항목 | 확인 내용 | 결과 기입 |
|---|---|---|
| 권한 | 소유/수집/재배포 승인 여부, 차단 정책 | 미확인 |
| 입력 유형 | 원격 URL 또는 로컬 빌드 | 미확인 |
| 사이트 구조 | SPA/SSR/정적 HTML, 링크 기반 네비게이션 | 미확인 |
| 탐색 가능성 | 메뉴, sitemap.xml, 본문 링크 우선순위 | 미확인 |
| 경계 | 허용 origin·path prefix, 제외 URL 규칙 | 미확인 |
| 페이지 수 | 예상 규모, pagination, 무한 스크롤 | 미확인 |
| 내용 | 코드 블록, 표, 이미지, iframe, 탭, 아코디언 | 미확인 |
| 리소스 | 외부 CDN·웹폰트·동적 요청 의존 여부 | 미확인 |
| 로봇 정책 | robots.txt, 이용약관, rate limit | 미확인 |
| 민감 정보 | 개인정보/비밀키/사내 API 주소 포함 여부 | 미확인 |

## 진단 실행 원칙
1. URL만 보고 프레임워크를 추측하지 않는다.
2. 승인된 URL에서 **최소 요청으로** sitemap/메뉴 및 링크 구조를 관찰한다. 접근 거부 시 중단한다.
3. 안전한 테스트용 fixture 사이트로 기술 PoC를 먼저 만든다.
4. PDF 생성 대상·탐색 경계·최대 페이지 수를 보고하고 승인받는다.

## 첫 적용 사례: KICC
`docs.kicc.co.kr`이 차단되었다는 현황을 우선한다. **운영 접근 우회나 자동 재시도 수집을 하지 않는다.** 문서 담당자가 제공하는 로컬 정적 빌드, 혹은 공식적으로 허용된 별도 테스트 주소가 있으면 그 범위에서만 진단한다. 실제 기술 스택은 미확인.

## Phase 0 산출물
`output/audit-report.md` (권한, URL 경계, 구조, 수집 규모 예상, 보안 우려, PoC 결과, 사용자 결정 사항). 실제 사이트에 접근할 수 없다면 테스트 fixture 결과와 필요한 입력만 기록한다.
